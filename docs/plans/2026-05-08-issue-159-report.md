## ① What shipped

Four changes that together close the rate-limit gap in `teamagent update --check`
and the auto-updater spawned at SessionStart:

1. **Token support** — `TEAMAGENT_GITHUB_TOKEN` → `GITHUB_TOKEN` → `GH_TOKEN`,
   sent as `Authorization: Bearer …`. Quota lifts from anonymous 60 req/h to
   authenticated 5000 req/h.
2. **ETag conditional GET** — response ETag persisted to
   `~/.teamagent/update-state.json`; next call sends `If-None-Match` byte-for-byte
   (weak `W/"…"` prefix preserved). `304 Not Modified` does NOT consume quota.
3. **Discriminated `FetchShaResult`** — replaces catch-all `Promise<string|null>`
   with `{ok:true, sha, etag, source}` / `{ok:false, reason, status, message}`.
   Seven failure reasons (`rate_limit_anonymous`, `rate_limit_authed`, `auth`,
   `not_found`, `server`, `network`, `parse`) map to per-reason CLI messages.
4. **Failure backoff** — two new `update-state.json` fields
   (`consecutive_rate_limits`, `next_check_after_ts`) drive exponential backoff
   `1h → 2h → 4h → 8h → 16h → 24h` (capped). Reset to 0 on first success. Does
   NOT touch `consecutive_install_failures` (which has its own 24h gate).

## ④ Risk assessment

| Risk | Mitigation |
|------|------------|
| ETag normalization breaks 304 path silently | github-api.test.ts asserts `If-None-Match` is sent byte-for-byte (weak `W/"…"` prefix preserved). Implementation never normalizes. |
| Old state files (no new fields) fail to parse | `parseUpdateState` typeof-guards each new field; unit test covers backwards-compat (state without new fields) and forward-compat (new fields with wrong types). |
| Rate-limit signal pollutes install-failure counter | `runUpdater` rate-limit branch explicitly does NOT touch `consecutive_install_failures` / `last_install_error`. Test `rate_limit_authed: increments counter and sets backoff without touching install_failures` locks the contract. |
| `checkCmd` ↔ `runUpdater` race on `last_branch_etag` | Both writers see the same upstream sha; when upstream advances, later writer wins. Worst case: one extra unconditional GET, no data loss. Documented in plan §2.5b. |
| `bin-updater.cjs` bundle cannot resolve `commands/update.js` for `resolveGithubToken` | Smoke test confirmed clean load. |
