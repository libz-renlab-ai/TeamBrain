### How we fix

**Worker A — `install-hook.ts` consolidated fixes** (findings 1, 2, 4, 7):

- **B-091 path stability**: stage all 4 hook bundles (`bin-pre-tool-use.cjs`, `bin-post-tool-use.cjs`, `bin-user-prompt-submit.cjs`, `bin-stop.cjs`) to `<homeDir>/.teamagent/hooks/` via `fs.copyFileSync` matching `installUserHook`'s pattern. Reference the staged path in `~/.claude/settings.json`. New helper `stageBundleToUserTeamagent(srcDistPath, homeDir): string` that returns the staged path.
- **JSON.parse safety**: wrap `readSettings` body's `JSON.parse(raw)` in try/catch. On parse error, log to stderr ("teamagent install-hook: ~/.claude/settings.json malformed; backing up to <path>.bak-<ts> and starting fresh") and treat as `{}`. Always take a `.bak-<ts>` backup of the existing file before writing.
- **Atomic write**: change `writeSettings` to write to `<path>.tmp-<pid>-<rand>` then `fs.renameSync` onto the target — POSIX rename is atomic. Same `writeSettings` is used for project-level too, so this fixes both layers.
- **B-086 legacy dedup**: add `isTeamagentEntry(entry, channel): boolean` that checks `_teamagentTag` OR command-contains-bundle-filename heuristic. Use it in `mergeUserLevelHooks` to filter both tagged and untagged entries before appending the new tagged one.
- **Concurrent-init advisory lock**: take an advisory lockfile at `<homeDir>/.claude/.settings.lock` for the read-modify-write window. Use `fs.openSync(lockfile, 'wx')` + retry-with-stale-detection (if lockfile age > 30s, treat as stale and overwrite). Release in `finally`.

**Worker B — `walk-up.ts` defense-in-depth + error-code-aware** (findings 3, 6, 9):

- **Trust-boundary B+A**:
  - Add a `PROJECT_MARKERS` const (mirror `session-start-logic.ts` list: `.git`, `package.json`, `pyproject.toml`, `pnpm-workspace.yaml`, `Cargo.toml`, `go.mod`, `pom.xml`, `build.gradle`, `build.gradle.kts`, `Gemfile`, `composer.json`).
  - At each candidate level: require BOTH `<dir>/.teamagent/knowledge.db` IS a regular file AND at least one project-marker exists in `<dir>`. Otherwise keep walking.
  - Stop the walk at `os.homedir()` (when `cur === os.homedir()`, return null after that iteration). Bind `homeDir` via param `findTeamagentRoot(start: string, opts?: { homeDir?: string })` so tests can inject.
- **Error-code distinction**: distinguish `ENOENT`/`ENOTDIR` (expected, keep walking silently) from `EACCES`/`ELOOP`/`EPERM`/`EIO` (unexpected, log to `process.stderr` once + abort that branch — return null rather than mask).
- **lstat for symlinks**: switch `fs.statSync` to `fs.lstatSync` so the `.teamagent/knowledge.db` symlink-to-foreign-file attack vector is rejected. Document the trade-off in the function's JSDoc.

**Worker C — `init.ts` executeInit guard + `bin.ts` help text** (finding 5):

- After `resolvePaths` in `executeInit`, call `findTeamagentRoot(paths.cwd, { homeDir: paths.home })`. If the returned ancestor is non-null AND is NOT exactly `paths.cwd`:
  - Default behaviour: abort with a `failed` step containing message "detected ancestor TeamAgent project at `<ancestor>`; refusing to create duplicate `.teamagent/` — cd to the project root or use `--force` to override."
  - Add `force?: boolean` to `InitOptions`. CLI flag: `--force-nested-init` (explicit; not `--force` to avoid shadowing other CLI conventions).
  - Update `bin.ts:445-468` help text to mention the new flag.

**Worker D — `session-start-logic.ts` autoInitDisabled walk-up** (finding 8):

- `autoInitDisabled(cwd: string)` currently checks only `cwd` and `os.homedir()`. Extend to walk up via `findTeamagentRoot`'s sibling pattern (or call `findTeamagentRoot` to find ancestor, then check that ancestor's `.teamagent/auto-init.disabled`). Symmetric with `decideAction`'s walk-up.

**Worker E — Tests + CHANGELOG** (findings 10, 11, 13):

- New tests (in existing test files; don't sprawl new files unless required):
  - `walk-up.test.ts`: 4 new cases — (i) project-marker required, (ii) `$HOME` cap stops walk, (iii) symlink-to-foreign-file rejected, (iv) EACCES on parent surfaces error not silent skip.
  - `install-hook.test.ts`: 6 new cases — (i) malformed settings.json triggers backup-then-rewrite, (ii) atomic write via tmp+rename, (iii) B-091 staged path is in `~/.teamagent/hooks/`, (iv) B-086 untagged legacy entry replaced cleanly, (v) concurrent init advisory lock contention, (vi) settings-symlink-to-readonly graceful failure.
  - `issue-161-walkup-integration.test.ts`: 1 new case — cwd-precedence test (raw.cwd=`<root>/sub`, `CLAUDE_PROJECT_DIR=<root>` → `projectDbPath=<root>/.teamagent/knowledge.db`).
  - `init.test.ts`: 1 new case for executeInit nested-init guard (default abort + `--force-nested-init` override).
  - `session-start-logic.test.ts`: 1 new case for ancestor's `auto-init.disabled` honored from child cwd.
- **CHANGELOG entry** in the repo's CHANGELOG file (or `docs/CHANGELOG.md` — check what exists). Mention `userLevel:true` default change + `--no-user-level-hook` escape hatch + `--force-nested-init` escape hatch.
- **Out of scope**: finding 12 (perf — memoisation) is genuinely cosmetic. Document in this plan that it is intentionally deferred — `findTeamagentRoot` is called once per hook invocation; ~12 statSync syscalls per cc tool-use is acceptable. If performance becomes an issue, memoise per-process in a follow-up. Adding the memoisation now adds cache-invalidation complexity without measurable user benefit.
