# fix(m5-viral): walk-up resolution for `.teamagent/knowledge.db` (issue #161)

## ① Task

修 issue #161：用户在子目录（非 init 时的根目录）启动 Claude Code 后，所有 teamagent hook 都用 `path.join(cwd, ".teamagent", "knowledge.db")` 解析项目知识库，没有 walk-up 逻辑 → 找不到父级 `.teamagent/knowledge.db` → DualLayerStore 退化成"只读 user-level global.db"，项目规则全丢。

修法：所有 hook 入口加 walk-up 解析。从 cwd 向上找最近祖先的 `.teamagent/knowledge.db`，与 git 找 `.git` 的行为一致。

这是产品级"病毒式传播"需求 #1（同机器任意目录都自动加载）的子问题。需求 #2（协作者 clone 全机器自动装 user-level hook）由独立后续 PR 处理。

**Anti-goals**（明确不做）：
- 不改 `teamagent init` 行为（仍在 cwd 建 `.teamagent`，不向上找祖先 init）
- 不做"知情同意 prompt"（鸭总确认走激进 viral 路线）
- 不改 user-level `~/.teamagent/global.db` 加载逻辑
- 不引入新 schema、新 port、新 contract

## ② Expected outputs

### 新增文件

- `packages/cli/src/find-teamagent-root.ts`
  - 导出 `findTeamagentRoot(cwd: string): string` —— 纯函数，不依赖 IO 注入（用 fs.existsSync 是允许的，shell 层）
  - 从 cwd 开始 `path.dirname` 向上 walk，找到第一个含 `.teamagent/knowledge.db` 的祖先目录返回
  - 找不到 → 返回 cwd 原值（保持现有 init 流程不变）
  - 跨平台 root 检测（Windows `C:\`、POSIX `/`）

  - 找不到任何祖先 → 返回 cwd
  - Windows drive root 边界正确停止（在 fixture 下用临时绝对路径模拟）
  - 符号链接 / 正常 path normalization
