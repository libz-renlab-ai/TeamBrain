How to verify the install

Three layers of verification — fastest first. Anything beyond layer 2 should run through a third-party judge harness per project convention.

Layer 1 — teamagent doctor

Single canonical CLI check. Reports per-channel install state, KB presence, plugin sync, and skill propagation.

$ pnpm teamagent doctor
# expects:
# hook-registered ✓ (6 channels)
# plugin-sync     ✓
# skills mirror   ✓
# kb              ✓
# warmup          ✓

Layer 2 — direct filesystem inspection

If doctor reports green, these paths must exist and contain TeamAgent entries.

$ ls ~/.claude/skills/teamagent/
$ jq '.hooks | keys' ~/.claude/settings.json
$ ls ~/.claude/plugins/installed/
$ ls .teamagent/knowledge.db

Layer 3 — judge-harness probe (canonical)

For an end-to-end install regression, dispatch through a third-party judge harness (per docs/plans/<...>/judge.md playbook convention) that runs teamagent init against a fresh-throwaway $HOME, captures raw stdout/stderr/exit codes to .judge/<run_id>/, and lets a separate LLM-judge read raw JSON only — never letting init grade itself. The probe must cover at minimum:

  • npm install -g teamagent from a clean prefix (≤3s budget per PR #147).
  • teamagent init in an empty repo + --target=claude (default).
  • teamagent init --target=codex — flag is accepted today (init.ts:282 skips Claude hook registration) but installs no Codex-side hooks; pending #291 for the real Codex installer branch.
  • teamagent doctor exit code = 0 with all rows green.
  • Re-running init is idempotent (no duplicate hook entries, no settings rewrite).
