## Root cause confirmed (codebase-verified)

- Source `packages/cli/src/bin-digital-twin-tap.ts` exists; `packages/cli/dist/bin-digital-twin-tap.cjs` builds fine locally.
- Release tarball is built by `packages/teamagent/tsup.config.ts`. Its `ENTRIES` dict (lines 5–15) lists only 9 bins; **`bin-digital-twin-tap` is not in the list**. The second tsup block's `entry` list (lines 93–103) also omits it. Hence the published dist is missing the file, `applyChannelOps` silently `continue`s past it, the install reports success, and the user-level Stop tap never registers — exactly as the issue body describes.

## Scope (Q1) — all 4 body steps, single PR

| # | Step | Where |
|---|---|---|
| 1 | Add `bin-digital-twin-tap` to **both** tsup ENTRIES dict (line 5–15) and the second tsup block's `entry` list (line 93–103) in `packages/teamagent/tsup.config.ts` | mandatory root-cause fix |
| 2 | `teamagent doctor` walks **every** entry referenced by the install table (`DIGITAL_TWIN_TAG` + any other tagged channel, both user-level and project-level scopes); `fs.existsSync` on each resolved `bundleFilename`; **exit non-zero** with a message naming the missing file | universal coverage, fail-loud |
| 3 | `applyChannelOps`: when `resolveBundle(...)` returns falsy or file is missing, write one stderr line `teamagent: skipping channel <ch> — bundle <file> not found`, then continue. **Not silenced in CI.** Install proceeds with whatever bundles exist. | partial install > silent failure; doctor is the strict gate, this is just "stop being quiet" |
| 4 | Add to `CHANGELOG.md` `## Unreleased` → `### Fixed`. **Do not modify the 0.11.0 section.** Phrasing: name the missing bundle + note that 0.11.0's "net 1 spawn per Stop" claim was effectively a no-op for downstream users until this fix. | standard CHANGELOG hygiene; follows `Publish per 10 PRs` (no patch release) |
