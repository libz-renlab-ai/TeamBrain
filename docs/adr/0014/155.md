### ⚠️ 必须修：跨订单 5 个真矛盾

**M1. flag 命名打架（order-1 ≠ order-3）**
- `order-1-preview/plan.md:29,94,95` 写成 `--skip-model`
- `order-3-install-merge/plan.md:39,61,86,118,119,…` 写成 `--skip-vector-model`
- 两边的 5 节 manifest 是同一段文本，flag 名必须统一。
- 鸭鸭建议：以 **`--skip-vector-model`** 为准（更明确，避免与未来其它 model 混淆）。

**M2. preview 命令名打架（order-1 ≠ order-4）**
- `order-1-preview/plan.md:20,90` 实际定义的是 `pnpm teamagent install --preview`（一个 flag）
- `order-4-doc-sync/plan.md:21,35` 写成 `teamagent preview`（一个独立 subcommand）
- 文档要让用户先跑 preview，但 preview 不存在那个 subcommand → 用户照文档敲会报 "command not found"。
- 鸭鸭建议：order-4 全文改成 `pnpm teamagent install --preview`，与 order-1 对齐。

**M3. 安装入口跟 issue body 打架（order-3 ≠ order-4 ≠ #155 issue 正文）**
- issue 正文明说"**不动 `curl | bash` 入口**，凶手是 AI 向导路径（post-clone 的 `pnpm teamagent ...`）"
- `order-3-install-merge/plan.md` 实现的是 `pnpm teamagent install`（AI 向导路径 ✓ 与 issue 一致）
- `order-4-doc-sync/plan.md:22,35,72` 却把"Order 3 合并后的单步命令"描述成 `sh /tmp/teambrain-install.sh`（curl|bash 路径 ✗）
- 这两条是**根本不同的安装通道**。order-4 把它们混淆了。
- 鸭鸭建议：order-4 改回"先 `pnpm teamagent install --preview` → 再 `pnpm teamagent install`"，curl|bash 那条单独留在 README 顶部 box 里、不动。

**M4. ADR-0001 #164 revision 让 `--skip-vector-model` 处于灰色地带**
- ADR-0001 已修订（2026-05-09）：vector deps 进 `dependencies`、model 文件由 detached `bin warmup` 后台下载、Stage 1 install ~3s 就返回。
- 如果模型下载已经是 detached 进程，那么 order-3 的 `--skip-vector-model` flag 在主进程语义里**啥也不卡**——它能 skip 的只是 spawn warmup 的那一步。
- 决策点（order-3 必须明确写到 plan 里）：是要 (a) 只跳过 spawn warmup，让用户后续手动 `teamagent warmup`；还是 (b) 把 model 下载从 detached 改回前台，flag 才有进度可跳？
- 鸭鸭建议：**(a)**（保留 ADR-0001 的 detached warmup 设计；flag 语义改为"don't trigger warmup spawn this run"，文档里写明）。

**M5. order-2 跟 CLAUDE.md "Functional Core, Imperative Shell" + ADR-0008 打边线**
- CLAUDE.md 元约束：`packages/core/` 禁止 import `fs` / `node:fs` / `node:child_process`。
- `order-2-resume-state/plan.md` 把"读写 `~/.teamagent/install-state/<project-id>.json`"放进 `packages/core/src/install-state/`。
- 纯函数（编码/解码/scoring）放 core 没问题，但 fs 操作必须留在 `packages/cli/` 的 imperative shell；plan 没明文区分这条边界。
- 鸭鸭建议：order-2 plan 加一节"Pure core / imperative shell split"，明确：
  - core 只导出 `serializeState(state) → string` / `parseState(string) → state` / `nextPendingStep(state) → stepId | null` 等纯函数；
  - 实际的 `readFileSync` / `writeFileSync` / 路径解析在 `packages/cli/src/install-state-io.ts`，调用 core 的纯函数。
