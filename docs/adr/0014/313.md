# Grilled result for #313 — Auto-update for every user

## Author goal (issue author 拍板)

> **每个用户都能自动更新到最新系统**。
> 不分网络环境（公司 NAT / 移动 / 咖啡店 / CI）、
> 不分操作系统（Windows / Mac / Linux）、
> 不依赖用户主动配置（不要求设 token、装 git、改 proxy）。

只有「连 GitHub 都连不上」的极端封闭环境例外（这种环境本来就装不上 TeamAgent，超出本 issue 范围）。

## Decision summary

抛弃 `api.github.com/repos/.../branches/release` 这条 60 req/hr 匿名通道（`packages/cli/src/github-api.ts:71`）作为 version-check 数据源。换成**自家三层架构**：

```
Tier 1 (主路): https://libz-renlab-ai.github.io/TeamBrain/latest.json
              CI 在每次 release-branch push 时 generate + commit
              GitHub Pages 通过 Fastly CDN 分发，无配额、毫秒级响应
              schema: { version, sha, releasedAt, tarball }

Tier 2 (兜底): registry.npmjs.org/teamagent/latest
              主路 timeout / 5xx 时回退；接受 npm latest 可能滞后一周（Publish per 10 PRs）

Tier 3 (人话): 两路都失败 → 显式提示，不再 silent 退避 24h
              文案 v1:
              "查不到新版本（Pages: <reason>, npm: <reason>）。
               可手动跑: npm i -g teamagent@latest
               或等下次启动重试。
               高级用户可设 TEAMAGENT_GITHUB_TOKEN 绕过此限制。"
```

**完全不再 touch `api.github.com`**。

注意：**install 路径不动** — 二进制 fetch 仍走 `github.com/.../archive/refs/heads/release.tar.gz`（`bin-updater.ts:74` 的 `PACKAGE_SPEC`），这是静态资产 URL，本来就不吃 API quota。

本 issue 已合并 #305（用户卡 0.10.1 + statusline 缺 TeamAgent 行 = 同根因的下游症状）。

## Author 拍板的关键取舍

1. **接受新增基础设施** — `latest.json` 由 CI 自动维护，提交到 `gh-pages` 分支。CEO ack：可接受 release-branch CI 生成 commit。
2. **拒绝 ABC 多源比对方案** — 多 source 带来 27 种失败组合，复杂度不划算。选择单一权威源（自家 Pages）+ 单一兜底（npm）。
3. **接受 npm 兜底滞后一周** — Tier 2 仅在 Tier 1 挂的时候启用，正常情况下用户拿到的就是 release-branch HEAD（毫秒级延迟）。
4. **三层一次性 ship** — 不拆分。本 issue 单 PR 完成。
5. **第 3 层人话文案** v1 由 implementer 起草，merge 前 reporter review。

## Task description

### Code changes
1. 新增 helper：`packages/cli/src/update/fetch-latest.ts`
   - `fetchLatestVersion(deps)`：先 Pages，失败回退 npm registry，永不打 `api.github.com`
   - 返回 discriminated result `{ ok: true, version, sha?, source: "pages" | "npm" } | { ok: false, pagesReason, npmReason }`
2. `packages/cli/src/commands/update.ts:274-318` (`checkCmd`)：调用 helper，把 SHA 比对改为 version 比对（保留 `last_installed_sha` 给 install/rollback path）。
3. `packages/cli/src/bin-updater.ts:313-316`：同样调用点切换。
4. `packages/cli/src/github-api.ts` 的 `fetchRemoteSha`：保留给 install path SHA pin（如 rollback 校验）；version-check 不再调它。
5. SessionStart upgrade banner 路径：silent backoff 改为 Tier 3 人话提示（具体文案见下）。

### CI infrastructure
6. `.github/workflows/release-branch.yml` 增加 step：每次 push 到 `release` 分支时，generate `latest.json` 并 commit 到 `gh-pages` 分支根目录。
   - 字段：`{ version, sha, releasedAt, tarball, generatedBy: "github-actions" }`
   - schema 文件：`docs/features/auto-update-channel.md` 记录字段定义、URL、guarantees
7. GitHub Pages 已部署（landing page 已在线），无需新启用。

### Documentation

   - `latest.json` schema + URL + 更新触发条件
   - 三层 fallback chain 描述
   - 给开发者解释「为什么不直接走 npm」（Publish per 10 PRs 滞后问题）
   - 标记 Out of scope（本 issue 之外的事，见下）
9. `CHANGELOG.md` Unreleased 段加一条用户可见的描述。

## Judge harness (3rd-party verification)

Fresh 机器、**明确不设** `TEAMAGENT_GITHUB_TOKEN` / `GITHUB_TOKEN` / `GH_TOKEN`：

### V1: Network capture
1. 装 `teamagent@0.10.1`（用户实际卡住版本）→ 升级到含本 issue 修复的 release version。
2. 触发 version-check：`teamagent update --check` foreground + SessionStart hook 连发 5×。
3. mitmproxy / instrumented `https.get` 抓所有 outbound HTTP。
4. **PASS** 条件（全部必须满足）：
   - 0 个请求打到 `api.github.com/*`
   - 0 个请求打到 `raw.githubusercontent.com/*`
   - ≥1 个请求打到 `libz-renlab-ai.github.io/TeamBrain/latest.json`
   - `teamagent update --status` 正确显示 latest version

### V2: Multi-environment matrix
模拟 5 种网络环境分别跑 V1：
- Direct internet (baseline)
- HTTP proxy (corporate)
- Throttled bandwidth (mobile sim)
- No outbound to `api.github.com` (firewall sim)
- No outbound to `registry.npmjs.org` (npm blocked sim)

每种都必须 PASS V1 主条件，npm-blocked 场景下应通过 Tier 1 单独工作。

### V3: Volume test
单机 10 分钟连跑 200× `teamagent update --check`。

**PASS**：无任何 rate-limit-shaped 失败；所有调用要么 200 (fresh)、要么 304 (cache hit)。

### V4: Tier 3 readability test
人为构造「Pages + npm 全挂」场景（mock DNS / iptables）。

**PASS**：用户看到的提示包含 ① 失败原因 ② 至少一条手动恢复路径 ③ 不是 "GitHub anonymous rate limit" 这种内部术语。

## Out of scope (本 issue 不做)

- 把 PAT 打包进 npm tarball（安全违规）
- 改二进制分发通道（仍是 GitHub Releases tarball）
- 调 backoff 指数（用不到了 — Tier 1 不需要退避）
- 离线 install / 老版本迁移路径
- CDN proxy（jsdelivr 等）— 三层架构已足够，不引入第三方
- `git ls-remote` 兜底 — 三层架构已足够，不依赖用户机器有 `git`
- 把 `Publish per 10 PRs` 节奏改成 per-PR publish — 是另一回事，本 issue 不动 npm 发布频率

## Operating constraints

- 单 PR ship（不触发 oversized split）
