## 根因定位

issue 现象 = `npm i -g github:libz-renlab-ai/TeamBrain#release` 在 Windows 上 partial install + 删旧目录。两层：

1. **必失败**：`tree-sitter-python` / `tree-sitter-typescript` / `web-tree-sitter` 三个 native 包在 Windows 上 install script 抛 `ENOENT spawn cmd.exe`
2. **partial install 后果**：npm reify 先删旧包再装新包；tree-sitter 安装失败 → 旧 teamagent 目录已不在

`packages/teamagent/package.json` line 31-33 把这 3 个包列为 hard dependency，且 README 已推 install.sh 路径（用户凭直觉走 `npm i -g` 撞坑）。

## 决策（鸭鸭签字 ✅）

### 🅰️ 移走 3 个 tree-sitter native 包 → 按需安装

- 从 `packages/teamagent/package.json` `dependencies` 移除：
  - `tree-sitter-python`
  - `tree-sitter-typescript`
  - `web-tree-sitter`
- 套用 #160 的 `vector-deps-absent` 模式（同 reason code 模板：`tree-sitter-deps-absent`）
- `packages/core/src/matcher/legacy/ast-context.ts:28` 的 `initAstMatcher` 已有完美 try/catch fallback：找不到模块 → 静默 return → `isInsideCommentOrString` 返回 false（保守模式：当作真命中，不过滤）
- 副作用：matcher 失去 comment/string 过滤 → 误报率小幅上升（不阻塞用户）
- 用户启用 AST 精准过滤：`TEAMAGENT_INCLUDE_OPTIONAL=1 sh -c "$(curl -fsSL https://raw.githubusercontent.com/libz-renlab-ai/TeamBrain/release/install.sh)"` 或显式 `npm install -g teamagent tree-sitter-python tree-sitter-typescript web-tree-sitter`

### 🅲️ install-time 自动备份 + rollback 安全网

- `release/install.sh` 在装新版前：
  - 检测现有 teamagent 安装位置（`npm root -g` / pnpm global root）
  - 用 `node:tar`（跨平台，避免 shell out）打包到 `~/.teamagent/backups/<ISO-timestamp>.tgz`
  - 保留最近 **3** 份，超过自动清理（FIFO）
- `packages/teamagent/postinstall.mjs` 在 catch 路径触发 rollback：
  - untar 最近一份 backup 到原位置
  - `recordSetupStatus("install", "rolled-back", "<backup-ts>")` 写到 `~/.teamagent/postinstall.log`
  - stderr 输出 `⚠️ teamagent install failed; restored backup from <ts>`
- 在 npm reify 失败时 install.sh 也要捕获 → 触发 rollback（npm 不会自动跑 postinstall.mjs）

### 🅱️ PowerShell installer — **暂缓**（治标不治本，先看 🅰️ 效果）

## 实现策略提示

- 沿用 issue #160 的 optional-deps-absent 模式 — 同套基础设施（`recordSetupStatus`, `optional-not-installed` reason code）
