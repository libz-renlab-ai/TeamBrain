# PR-PLAN — fix the 4 adversarial findings on PR #183

> Per `docs/PR-PLAN.md`: post-PR review surfaced issues → block merge → write
> this PR-PLAN → fix on the SAME PR branch → re-review until PASS. NO follow-up
> issue. Squash-merge later.

The Claude adversarial subagent (Step 5.7 of `/review`) raised 4 findings on PR
#183. Findings #1 and #2 are real defects (verified by manual trace + code
read); #3 is robustness; #4 collapses into the #1 fix.

## ① Task description

### What we're doing

| # | Finding (verified)                                               | Fix |
|---|------------------------------------------------------------------|-----|
| 1 | `parseDemoHookArgs` silently corrupts URLs/shell strings containing `&` or `;` (e.g. `url=https://x.com/?a=1&b=2` → `{url: 'https://x.com/?a=1', b: 2}`) | **Drop the `;`/`&` magic separator entirely.** Keep two forms: space-separated argv slots (canonical, unchanged from pre-PR) and a single-slot JSON object form (added in this PR). Update help text. The `;`/`&` is too colliding with real shell metacharacters for an offline teaching tool to safely auto-split. |
| 2 | `hook-shell/index.ts` only downgrades `StdoutRenderer`'s renderMode; `ctx.visibility` is still `verbose` and propagates to `createPreToolUseHandler`, which writes a `◈ TeamAgent: ✓ <tool> 放行 (检查 N 条规则)` `systemMessage` into the stdout JSON envelope on every clean pass — so the user-visible "noisy by default" still leaks through stdout even when stderr is quiet. | Compute `effectiveVisibility` once (the same value used for renderMode), and pass it to `createPreToolUseHandler` via the context's `visibility` field. Add regression test asserting the stdout JSON envelope has no `systemMessage` on clean-pass when `TEAMAGENT_HOOK_VERBOSE` is unset. |
| 3 | `executeTry` has no per-case `try/catch`; one thrown `executeDemoHook` aborts the whole 5-case demo mid-render, leaving stale `[1/5]` output and no closing line. | Wrap each case in `try/catch`; on failure print `❌ <label>: <short err>` and continue to the next case. The demo's promise of "5 cases, 30 seconds" must hold even when one fixture trips a runtime issue. Add a regression test that injects a throwing `executeDemoHook` (or uses a fixture path that deliberately fails) and asserts the demo runs to `演示完成。`. |
| 4 | `splitMultiField` chooses `;` over `&` if both are present — separator precedence is documented nowhere. | Moot — fix #1 removes `splitMultiField` entirely. |

### What we're NOT doing

- **Not changing the project default visibility.** `parseVisibility` still
  returns `"verbose"` when `TEAMAGENT_VISIBILITY` is unset; only the *hook
  channel*'s effective visibility downgrades. Other hook users on this default
  see no behaviour change.
- **Not adding a `--multi` CLI flag.** The JSON form already covers multi-field
  parsing unambiguously; another flag would be additional surface area for
  small benefit.
- **Not changing the JSON envelope schema.** Claude Code consumes
  `hookSpecificOutput.permissionDecision` etc.; we only suppress the
  human-prose `systemMessage` when verbose isn't opted in.
- **No follow-up issue.** Per `docs/PR-PLAN.md`, fix on this PR or block.

  `;` / `&` mention with the JSON form (which is what's actually supported).

### CLI-visible contracts

- `pnpm teamagent demo hook Fetch 'url=https://x.com/?a=1&b=2'` parses to
  `{ url: 'https://x.com/?a=1&b=2' }` — single key, original value preserved.
- `pnpm teamagent demo hook Bash 'command=echo hi; rm -rf /'` parses to
  `{ command: 'echo hi; rm -rf /' }` — single key.
- `pnpm teamagent demo hook Write '{"file_path":"a","content":"b"}'` parses
  to `{ file_path: 'a', content: 'b' }`.
- `pnpm teamagent --help` `demo hook` line mentions JSON form (not `;`/`&`).
- Default hook (no env) returns a JSON envelope with **no** `systemMessage`
  on clean pass. With `TEAMAGENT_HOOK_VERBOSE=1`, the envelope contains the
  `◈ TeamAgent` systemMessage.
- `executeTry({ delayMs: 0, executeDemoHookForCase: throwOnIdx2 })` (or
  equivalent injection) returns exitCode 0 with all 5 case headers and the
  closing `演示完成。`.

### Anti-goals

- The JSON envelope schema (Claude Code's contract) stays unchanged —
  only conditional fields are gated.
- The `[advanced]` marker on `demo hook` help (added in PR #183) stays.
- `parseVisibility` semantics for non-hook commands stay unchanged.
- `executeDemoHook` itself stays untouched (it's W1's slice; we only change
  W1's outer parser).

### Targeted regression probes

1. URL parser probe — manual:
   ```
   node -e "
     const { parseDemoHookArgs } = require('./packages/cli/dist/commands/demo-hook.js');
     const r = parseDemoHookArgs(['Fetch', 'url=https://x.com/?a=1&b=2']);
     if (r.toolInput.url !== 'https://x.com/?a=1&b=2') throw 'URL corrupted';
     if (r.toolInput.b !== undefined) throw 'spurious b key';
     console.log('URL probe PASS');
   "
   ```

2. Hook envelope probe — exercise the real `bin-pre-tool-use.ts` channel
   (per W3's corrected probe in their report):
   ```
   echo '{"hook_event_name":"PreToolUse","tool_name":"Read","tool_input":{"file_path":"/tmp/x"},"tool_use_id":"t1"}' \
     | node packages/cli/dist/bin-pre-tool-use.cjs > /tmp/envelope.json
   jq -e '.systemMessage // "" | test("放行") | not' /tmp/envelope.json
   # → exit 0 (no 放行 in systemMessage)
   TEAMAGENT_HOOK_VERBOSE=1 echo '{"hook_event_name":"PreToolUse","tool_name":"Read","tool_input":{"file_path":"/tmp/x"},"tool_use_id":"t1"}' \
     | node packages/cli/dist/bin-pre-tool-use.cjs > /tmp/envelope-verbose.json
   jq -e '.systemMessage | test("放行")' /tmp/envelope-verbose.json
   # → exit 0 (verbose flag flips the systemMessage on)
   ```

3. `try.ts` resilience probe — vitest-only (the throwing path is too fiddly
   to probe via shell):
   ```
   pnpm vitest run packages/cli/src/__tests__/try.test.ts -t 'continues past failed case'
   ```
