# 4. 事件存储模型：必须是 append-only raw event store

## Grill 问题

完整 prompt 和 host-specific payload 怎么存？

## 可选答案

A. 每个 plugin 自己存
B. 只存 session transcript
C. 只存 normalized event
D. append-only raw event + normalized event
E. 业务表直接存最新状态

## 裁决

选 **D**。

```txt
raw_events:
  event_id
  event_type
  host = claude | codex | audio | github | app
  team_id
  project_id
  member_id
  agent_install_id
  session_id
  timestamp
  raw_payload
  raw_prompt_text
  content_hash
  payload_encryption_key_ref

normalized_events:
  event_id
  event_type
  project_id
  member_id
  session_id
  work_item_id
  summary
  tags
  presence_delta
  payload_ref
```

理由：#290 已经说明 Codex `SessionStart` 的 `systemMessage` envelope 形状可能不同，需要 Codex-native adapter；如果 plugin 直接消费 Claude/Codex 原始 payload，host 差异会污染所有业务逻辑。citeturn596084view0

正确边界是：

```txt
Claude/Codex/audio adapters:
  host payload -> raw_event -> normalized_event

plugins:
  consume normalized_event
  optional request raw payload for evidence
```

# 13. #290/#291：Codex 和 Claude 接入必须 host adapter 化

## Grill 问题

Codex hook 怎么接？

## 可选答案

A. 复制 Claude hook 脚本，改到能跑
B. 完全重写 Codex 路径
C. Claude/Codex 共用能共用的 bin，shape 不同时加 adapter
D. 先只支持 Claude
E. 先只支持 Codex

## 裁决

选 **C**。

#290 明确要求 `.codex/` config 被提交和追踪，Codex adapters 要与 Claude scripts 并存，不能 mutation Claude scripts；它还特别点出 `SessionStart systemMessage envelope` shape 不同处要加 Codex-native adapter。citeturn596084view0

架构：

```txt
.claude/settings.json
  -> Claude hook
  -> claude adapter
  -> /v1/events

.codex/hooks.json
  -> Codex hook
  -> codex adapter
  -> /v1/events

server:
  raw_events
  normalized_events
```

不能这样：

```txt
Codex hook 直接改 Claude script
```

也不能这样：

```txt
每个 plugin 自己适配 Claude/Codex payload
```
