# P7 — TTHW 5分钟录屏脚本

**意图**：landing → install → demo → PreToolUse 拦截，total_budget 300s。

## 6 步链路（总预算 300s）

| id | action | expected_s | 关键失败信号 |
|----|--------|-----------|--------------|
| `open-landing` | 打开 landing，等待 hero 渲染 | 8 | 加载超时 10s / install 命令不可见 |
| `copy-install` | 选中 install one-liner，Cmd+C | 5 | 命令截断 / 剪贴板为空 |
| `paste-terminal` | 开终端，Cmd+V | 5 | 粘贴失败 / 命令只粘贴一半 |

# P8 — npm vs tarball 发布路径

**探针意图**：给出两条发布 `@teamagent/cli`（当前 `private:true`）的 commit 序列，
并明确推荐路线。

## 路线 A — npm publish

3 个 commit：

| order | subject | 关键变更 |
|-------|---------|---------|
| 1 | `chore(cli): remove private flag and point bin to compiled dist` | `package.json` 去掉 `private:true`，`bin` 改指 `dist/bin.js`，tsup 加 noExternal |
| 2 | `chore(cli): add .npmignore and fix bin shebang` | `.npmignore` 排除 `src/`、`__tests__/`、config 文件 |
| 3 | `ci(cli): add npm publish workflow for @teamagent/cli` | `.github/workflows/publish-cli-npm.yml`，tag 触发 |

**风险**：npm 2FA/OTP 要求自动化 token；workspace:* 依赖打包顺序约束；@teamagent/* 子包须先发布或全部 bundle。

**回滚**：逐一 revert 3 个 commit，恢复 `private:true` 和 `bin: ./src/bin.ts`。

## 路线 B — GitHub Releases tarball（推荐）

3 个 commit：

| order | subject | 关键变更 |
|-------|---------|---------|
| 1 | `chore(cli): prepare package for tarball distribution` | 保留 `private:true`，设 `files=[dist/, package.json, postinstall.mjs]` |
| 2 | `build(cli): create install.sh for GitHub tarball installation` | `install.sh` 从 release asset 拉 tarball，建 bin symlink |
| 3 | `ci(cli): add GitHub Releases tarball upload workflow` | `.github/workflows/publish-cli-tarball.yml`，tag 触发上传 asset |

**风险**：curl|bash 安装方式部分环境受阻；asset 名变更导致 install.sh 失效；无 npm 自动依赖解析。

**回滚**：逐一 revert 3 个 commit，删 `install.sh` 和 workflow。

## 结论

```json
{ "chosen_path": "B", "rationale": "Route B avoids npm 2FA/OTP, workspace-dep bundling complexity, and npm scoped-package publish-order constraints; GitHub Releases + install.sh is self-contained and matches how the already-published teamagent package is distributed." }
```

## 对 research.md §D 的贡献

> 路线 B（tarball）与现有 `teamagent` 包发布方式一致，避免 npm scope 权限和
> 依赖打包顺序问题，3 个 commit 即可上线；install.sh 的 curl|bash 风险可通过
> SHA256 校验和文档说明缓解。
