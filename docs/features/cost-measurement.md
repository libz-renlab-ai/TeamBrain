# Token cost measurement — how to reproduce the issue #343 ablation

This doc is the **operational recipe** for re-running the Counterfactual
Ablation that answered issue #343 ("装 TB 会不会增加 token 成本？").

Boss-facing answer + headline numbers: see
[`docs/reports/2026-05-12-issue-343-tb-token-cost-summary.md`](../reports/2026-05-12-issue-343-tb-token-cost-summary.md).
Project canon for *why* we use scipy paired t-test: see
[`docs/verify/E2E-LEARNING.md`](../verify/E2E-LEARNING.md).

## What gets measured

For each task in the corpus, the same prompt is sent to Claude through
two configurations, **same install footprint** of TeamBrain on both:

| Group | Hooks installed | Env | Effect |
|---|---|---|---|
| `teamagent` | Yes | unset | TB hooks fire, matcher injects, attribution emits |
| `teamagent-disabled` | Yes | `TEAMAGENT_DISABLED=1` | All 8 hook handlers early-return (PR-1's master kill switch) |

`baseline` group (no hooks installed) is **retained for reference but
NOT the paired control** — pairing `teamagent` vs `baseline` would mix
two variables (install + runtime); `teamagent` vs `teamagent-disabled`
isolates the runtime cost cleanly.

Each task records `tokensIn`, `tokensOut`, `cacheReadTokens`,
`cacheCreationTokens` from the Claude SDK `usage` field. The metric for
ablation is the per-task total (sum of all four).

## Recipe (5 commands)

```bash
# 1. Build hook bundles (required: bin-*.cjs files in packages/cli/dist/)
pnpm -F @teamagent/cli build

# 2. Set up a run-id so evidence lands somewhere reproducible
RUN_ID="$(date +%Y%m%d-%H%M)-$(git rev-parse --short HEAD)"
EVID_DIR="docs/plans/2026-05-12-issue-343-pr2/evidence/$RUN_ID"
mkdir -p "$EVID_DIR"

# 3. Run the bench (~10-15 min, ~$1-3 burn at Haiku 4.5 prices)
pnpm -F @teamagent/benchmark bench \
    --groups=teamagent,teamagent-disabled \
    --tasks=all \
    --runs=1 \
    --output-json="$EVID_DIR/bench-report.json" \
    --output-md="$EVID_DIR/bench-report.md"

# 4. Install scipy (one-time, dev-only)
pip install scipy numpy

# 5. Run the paired t-test
python scripts/judge/issue-343-ablation.py \
    "$EVID_DIR/bench-report.json" \
    "$EVID_DIR/ablation.json"
```

## Auth

The benchmark uses `@anthropic-ai/claude-agent-sdk`, which bundles its
own `cli.js`. If your local `claude` CLI is OAuth-logged-in, the SDK
inherits that auth — no `ANTHROPIC_API_KEY` env needed.

If running headless / in CI / on a fresh machine, set:
```bash
export ANTHROPIC_API_KEY=sk-ant-...  # or your MiniMax-routed equivalent
```

## Extending the corpus

To add a new task:

1. Drop a JSON in `packages/benchmark/fixtures/tasks/NNN-slug.json`
   with the same shape as `008-var-to-const.json`.
2. Add a matching rule to BOTH `packages/benchmark/fixtures/groups/teamagent/seed.sql`
   AND `packages/benchmark/fixtures/groups/teamagent-disabled/seed.sql`
   (they MUST stay byte-identical — `corpus-ablation.test.ts` asserts this).
3. Re-run the bench. `judge.py` automatically pairs the new task as long
   as both groups produced results.

## Why scipy paired t-test (and not something simpler)

- **Paired**: same task is run under both conditions, so we subtract
  within-task noise (cache state, prompt length, task complexity).
- **t-test, not z-test**: we don't know population variance.
- **scipy.stats.ttest_rel**: pre-dates this repo by a decade, math
  contract is in textbooks, no LLM-fakeable in-house implementation.
- **95% CI on the mean delta**: per `stats.t.interval(0.95, df=n-1)`.
  Gives the boss a bound, not just a point estimate.
- **Reject null at α=0.05** (not 0.01): we're answering "is there a
  measurable cost increase", not "is there a rare extreme effect". 0.05
  is the standard threshold for engineering decisions.

## Known limitations (read these before re-running)

- **n=17 has limited power**: detecting a true mean delta of ~3000 with
  stddev ~11000 needs n≈30-50 for 80% power. Add more tasks before
  claiming "definitively no effect."
- **Cache tokens dominate (~95%)**: marginal hook cost is tiny vs
  baseline prompt cache. Real fresh-cache runs (no `cacheReadTokens`)
  would show a larger relative delta — but those are rare in normal
  usage.
- **Literal-instruction tasks under-test TB**: the agent obeys "use var"
  over the matcher's "use const" nudge. Future corpus should include
  tasks where the anti-pattern is implicit (agent picks lib without
  explicit instruction).
- **Single run per task**: vitest's flake-detection would normally run
  ≥3 times. We didn't because budget. `--runs=3` would 3× the API
  spend; judge.py averages within-(task,group) before pairing, so the
  output schema is unchanged.

## Sibling: issue #332 Counterfactual Ablation (different metric, same library)

`scripts/ablation/ttest_l4.py` runs the same `scipy.stats.ttest_rel`
recipe for a **different metric**: rule-firing event counts (not
tokens). It's used by the nightly insurance lane to gate m5 rule
propagation L4. Both scripts are independent and live in different
directories on purpose — issue #343 measures token cost, issue #332
measures learning-event efficacy.
