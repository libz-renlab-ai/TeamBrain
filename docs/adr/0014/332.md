# Grill log — issue #332: Test team-rule propagation between two users (A → B)

Per [ADR-0014](../0014-save-grilled-comments-to-adr.md), this is the durable
archive of the grill that produced the `grill-ready` comment on issue #332.
The GitHub comment is the operational trigger for driver dispatch; this
file is the indexable, split-safe record of how the decisions were made.

## TL;DR — what is being tested

**用户 ↔ 用户 运行时规则传染管线**（不是 `teamagent init` 项目→用户配置传播）：

```
A's KB → m5-share → .teamagent/team/A/<rule_id>.json
       → git push/pull (or fs copy)
       → m5-sync --apply → B's KB → matcher → B's session 行为变化
```

测试断言的不是"协议正确"——是 **B 的 Claude session 行为真的变了**：
PreToolUse 真的拦了、UserPromptSubmit 真的注入了、KB 的 hit_count 真的累计了。

## Terminology resolved

| Term | Resolved meaning in #332 scope |
|---|---|
| **rule propagation** | 用户↔用户 KB 同步（m5-share / m5-sync），**不是** project-to-user `teamagent init` 那条 INIT-PROPAGATION |
| **employee A / B** | 两个独立 user/HOME，可以是真两台机器，也可以是同机两份临时 HOME |
| **transit** | A 的 share 文件到达 B 的物理通道；候选：git push/pull、fs copy、共享目录 |
| **L4** | 端到端行为验证层级（vs L1 文件落地 / L2 sync merge / L3 matcher 检索） |
| **hot path** | mock LLM responder、纯 teamagent 代码路径、毫秒级 (PR-gate) |
| **cold path / insurance lane** | 真 `claudefast -p` 子进程、真 Anthropic API、ablation t-test (nightly) |
| **observable** | 不看 LLM 自由文本；看 attribution_events / hook_outcomes / kb_state 三类结构化字段 |

## Crystallized decisions

| # | 决策维度 | 选定值 | 拒绝的候选 + 理由 |
|---|---|---|---|
| 1 | 测试层级 | **L4 端到端行为变化** | L1/L2/L3 太浅，不能证明 B 真用上规则 |
| 2 | 测试环境 | **A：单机双 HOME hermetic 仿真** | B 真双机不进 CI；C docker compose Windows runner 不支持 |
| 3 | A→B Transit | **④ 双轨：fs copy 快道 + bare git 慢道** | 单 fs copy 不测 git 通道事故；单 git 太慢；共享目录无传递语义 |
| 4 | Rule fixture | **④ 三种全套：avoidance + practice + learning** | 单 ① avoidance 覆盖太窄 |
| 5 | B session 实例化 | **④ 双 verdict：mock LLM (PR-gate) + 真 claudefast (nightly)** | 单 mock 假掉 Claude Code 真集成；单真过贵 |
| 5b | Insurance lane 时机 | **day-1 ship**（不延后到 phase 2） | 延后等于无 e2e 集成保护 |
| 6 | Ablation N | **② 分层 N**：avoidance=10、learning=10、practice=30 | ① 均匀浪费；③ 厚 N 成本爆；④ 极薄 N 废契约 |
| 6b | Prompt 集来源 | **(a) 手写 paraphrase 集** (git-tracked) | (b) LLM 生成不可重现；(c) DUCKPLAN PII 跨 scope |
| 7 | API key 管理 | **(a)+(c)**: 复用 `MINIMAX_API_KEY` (per ADR-0013) + `TEAMAGENT_NIGHTLY_MAX_USD=10` budget guard | (b) 双 key 对单 issue 不增量 |
| 8 | p-value 阈值 | **α-2: p ≤ 0.01** | α-1 (0.05) flake 风险高；α-3 (0.001) 与 N 决定冲突 |
| 8b | Byte-diff 严格度 | **β-2: strict + mask 5 字段** (`timestamp` / `uuid` / `tmpdir` / `pid` / `cwd_abs_path`) | β-1 strict 被随机字段打挂；β-3 语义比对失去字节锚点 |
| 8c | Replay tier | **γ-3: `--tier=a` hard gate + `--tier=b` advisory** | γ-2 `--tier=all` 引入 LLM-judge 违反契约 |
| 9 | TRIAGE-AND-SPLIT | **B 留作 single PR**（maintainer override，未拆） | A 拆 3 child 的 size 信号被 maintainer 评估后 hold scope |

## Two deterministic third-party harnesses (verdict gates)

Per `docs/verify/E2E-LEARNING.md`，两个 LLM-unfakeable 第三方 harness 并行 verdict：

### Harness 1: Counterfactual Ablation

- 工具：`scipy.stats.ttest_rel`（pre-existing 第三方科学计算库）
- 数据：每条 rule N 个手写 paraphrase prompt，rule-ON / rule-OFF 双 run
- 观察值：hook fire / block / citation 结构化整数
- PASS：p ≤ 0.01 且 Δ 方向符合预期
  - avoidance: rule-ON block > rule-OFF (≈0)
  - learning: rule-ON hit_count > 0, rule-OFF = 0
  - practice: rule-ON inject > rule-OFF

### Harness 2: Regression Replay (byte-diff)

- 工具：`pnpm teamagent fixture replay --tier=a --slug m5-rule-propagation-l4-{avoidance,practice,learning}`
  （或新 sibling `pnpm teamagent m5-replay --slug ...`——见 open design question 1）
- 数据：`tests/fixtures/scenarios/m5-rule-propagation-l4/<rule>/expected.events.jsonl` (git-tracked, immutable)
- 比对：B 端 actual events jsonl vs expected events jsonl
- Mask 字段（git-tracked `.replay-mask.yaml`）：5 项见决策 8b
- PASS：strict equality on all unmasked fields

**两个 harness 必须同时 PASS 才算 verdict 通过；任一失败 = CI 红灯。
没有 LLM-as-judge 参与 verdict 决策。**

## Codebase context discovered during grill

- 现有 `pnpm teamagent fixture replay --tier=a` (`packages/cli/src/commands/fixture-replay.ts:97`) 只接受 `tier="a"`；`tier=b/c` 在 `parseTier` 抛错，**当前 unimplemented**
- 现有 tier=a 跑的是单用户 correction loop（correction-detect → rule-extract → intercept）；**不直接覆盖多用户 m5-share/sync 传播**
- 现有 scenarios 在 `fixtures/scenarios/index.ts`（6 个：python-version / tech-choice / api-hallucination / security / workflow-order / moment-dayjs）
- 现有 `FsTeamRuleStore` (`packages/adapters/src/m5/fs-team-rule-store.ts`) 已实现 `.teamagent/team/<claim_author>/<rule_id>.json` 原子写 + LWW
- 现有 `m5-share` (`packages/cli/src/commands/m5-share.ts`) 已做 secret scan + scope classify + `isTeamRulePathLengthSafe` Windows MAX_PATH 边界
- 现有 `m5-sync` (`packages/cli/src/commands/m5-sync.ts`) 已实现 LWW merge + `--apply` 写 KB

## Open design questions (preserved for implementer)

实现侧需要选边，但**不在 grill 决策范围**：

1. **Fixture replay 扩展 vs 新 sibling 命令**
   - (i) 扩 `fixture replay` 的 Scenario type 加 `setup.steps[]` hook → 影响现有 6 scenario 兼容性
   - (ii) 开 sibling `pnpm teamagent m5-replay --slug ...` → 解耦但有 verdict 渲染重复
   - 维护者倾向 (ii)；实现者最终拍板
2. **Mock LLM responder 放包**：`@teamagent/adapters` vs 新建 `@teamagent/testing`？
3. **Ablation runner 语言**：Python (scipy, 与 E2E-LEARNING.md canonical 一致) vs Node (jstat)？
4. **Mock LLM 签名复杂度**：echo / keyword-rule / 简易状态机？必须复现 PreToolUse + UserPromptSubmit 触发条件

## Acceptance criteria

- [ ] 3 条 fixture scenario 文件齐全且 commit
- [ ] Hot path (mock LLM) PR-gate 跑通：3 scenario × 2 condition = 6 fixture diff 全绿
- [ ] Cold path (真 claudefast) nightly 跑通 1 次：3 scenario × N × 2 = 100 calls，p ≤ 0.01 且 Δ 方向对
- [ ] Budget guard：`TEAMAGENT_NIGHTLY_MAX_USD=0.01` 注入后 nightly 在 API 调用前 fail-fast
- [ ] Cleanup：tmpA/tmpB/bare repo 测试结束 `rm -rf`，无残留
- [ ] Windows runner：hot path 跑通（路径 separator + `isTeamRulePathLengthSafe` 边界）

## Out-of-scope (explicit exclusions)

- ❌ 真双机（A、B 各一台真笔记本）—— release smoke 手动，写进 `docs/feature-verification.md`
- ❌ 真 GitHub remote —— bare git repo 是 transit 替身
- ❌ 跨组织 / 跨 repo 规则同步
- ❌ `tier=b` / `tier=c` LLM-judge 路径（现 unimplemented，未来 advisory only）
- ❌ INIT-PROPAGATION (`teamagent init` 项目→用户) —— 独立 issue
- ❌ Personal scope 隔离（A 标 personal 不该 share）—— 独立 issue
