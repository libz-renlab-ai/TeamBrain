# Issue-84 Probes: P3 (GitHub Pages 拓扑) + P4 (install.sh 安全审计)

产物路径：`.fastprobe/issue84/p3.json` / `.fastprobe/issue84/p4.json`

---

## P3 — GitHub Pages source 三选一对比

**Probe intent**：评估三种 GitHub Pages source 配置的 trade-off，输出结构化比较 JSON，为 issue-84 落地页部署决策提供依据。

**产物路径**：`.fastprobe/issue84/p3.stream.json` → `.fastprobe/issue84/p3.json`

**Findings**：

- **Option 1 (gh-pages 分支根目录)**：迁移成本 `low`，无需 CI，但双分支维护易脱节，分支体积随时间膨胀
- **Option 2 (main 分支 /docs 目录)**：迁移成本 `low`，无需 CI，单一事实来源，编辑最直接；cons 是 /docs 从根目录 served 需要注意路径映射，源码目录混入发布产物
- **Option 3 (apps/landing/dist via actions/deploy-pages)**：迁移成本 `high`，必须 CI，构建与部署分离验证后才发版，支持 preview deployment；代价是多 1-3 分钟延迟，workflow 本身需版本控制
- **Recommendation = 2**：`docs/` 方案最轻量，单分支工作流，源码即部署物，迁移与回滚成本最低；初期迭代最快

## P4 — install.sh curl pipe 安全审计

**Probe intent**：对 `curl -fsSL .../release/install.sh | sh` 安装方式做多维度安全风险评估，输出 must-have-in-v1 行动项。

**产物路径**：`.fastprobe/issue84/p4.stream.json` → `.fastprobe/issue84/p4.json`

**Risk findings（共 10 条，按严重度）**：

- **HIGH** S-01：release 分支无保护，仓库入侵/maintainer 账号接管可植入恶意脚本
- **HIGH** S-02：raw.githubusercontent.com 无 SRI，CDN 边缘节点或 BGP 劫持可替换响应体
- **HIGH** P-01：URL 不含版本 tag/commit SHA，内容更新后脚本静默变化用户无感知
- **HIGH** N-03：`| sh` pipe 直接执行，用户无机会 review 内容后中止破坏性操作
- **MED** T-01、P-02、F-01、F-02：TLS 降级风险、GitHub 限流、无 fallback URL
- **LOW** T-02、N-01、N-02：弱 cipher suite、redirect 域名未校验、企业代理透明度

**Must-have-in-v1（7 项）**：

1. URL 必须版本化（包含 tag/commit SHA），禁止 release/latest 浮动标签
2. 提供 SHA-256 校验和文件，执行前校验（install.sh + install.sh.sha256 双文件）
3. curl 显式指定 CA bundle，禁止静默 TLS 降级
4. 默认两步执行（download + execute），禁止默认 `pipe | sh`
5. install.sh 内置 redirect URL 域名检查，防止 redirect 外泄
6. 提供至少一个 fallback 下载端点（Release asset 直链或 CDN 镜像）
7. install.sh 支持 `--no-run / --dry-run / --verify` 模式，用户可先查看

**Follow-up (v1 之后)**：Sigstore cosign / GPG 签名、SLSA Provenance Level 1、离线分发方案、安全响应预案
