# Archive 6 hypothetical port seams; future ports must prove ≥2 real adapters

We move six existing port interfaces — `CorrectionDetector`, `SuccessDetector`, `CandidateQueue`, `ErrorSignalCollector`, `BootstrapPort`, and `TeamRuleStorePort` — from `packages/ports/src/` into a sibling `packages/ports/src/_archived/` drawer (along with their contract test suites where present) because each of them satisfies LANGUAGE.md's "one adapter = hypothetical seam, two adapters = real seam" deletion-test failure: every one of these ports has exactly one production adapter, callers import that adapter directly without going through the port type, and contract tests (where they exist) only validate the lone adapter against itself, providing zero leverage and accumulating maintenance tax (interface documentation, contract test upkeep, type indirection) without paying back option value. The archived files remain on disk under `_archived/` rather than being `git rm`-deleted so that future maintainers have visible, browseable evidence of the historical interface design when (or if) a second real adapter ever appears — at which point the port can be moved back out of the drawer with full historical context. The archive drawer also serves as a forcing function: any future PR proposing a new port must either present two concrete adapters at the time of introduction or explicitly opt into the drawer's "single-adapter-known-hypothetical" status with a TODO to revisit before M{N+1}.

## Considered Options

- **(a) `git rm` the 6 port files outright** — Rejected. The interfaces represent past design intent that future maintainers may want to reference when adding a real second adapter (e.g., an LLM-judged `CorrectionDetector` to complement the rule-based one). `git rm` makes that history one `git log -- <path>` archaeology session away, which is enough friction to dissuade casual lookup; an `_archived/` drawer keeps the file one `ls` away while still being clearly out of the live surface area.
- **(b) Mark the 6 ports `@deprecated` and leave them in place** — Rejected. Deprecation labels still cost reading time for every new contributor scanning `packages/ports/src/`, still appear in IDE autocomplete, and still require type-checking. The maintenance tax we wanted to remove is barely reduced. Worse, "deprecated" implies "still usable for now", whereas these ports are not just deprecated — they are actively misleading about the architecture (suggesting a seam exists where none does).
- **(c) Spin off a separate `@teamagent/ports-archived` package** — Rejected. Adds a new package to the workspace, `package.json` to maintain, build target to wire — the maintenance overhead of being its own npm package outweighs the benefit of physical separation. A subdirectory inside `@teamagent/ports` achieves the separation without the workspace overhead.
- **(d) Keep the ports and pay the tax, betting that second adapters will eventually arrive** — Rejected for the four ports with no second adapter on the active roadmap (`CorrectionDetector`, `SuccessDetector`, `CandidateQueue`, `ErrorSignalCollector`). For the two M5 viral-sync ports (`BootstrapPort`, `TeamRuleStorePort`), `docs/CONTEXT.md` explicitly states that "git-backed transport: TeamBrain 唯一 team-scope 同步通道", which makes a second prod transport a CONTEXT.md violation, not a port-API question. Until and unless CONTEXT.md is amended to permit a second transport (S3, central server, P2P), these two ports are also hypothetical and belong in the drawer.

## Consequences

- **`packages/ports/src/index.ts` no longer exports the 6 archived port types.** Any out-of-tree consumer (none known today) that imported `CorrectionDetector` from `@teamagent/ports` will see a TypeScript error. Inside the monorepo, all 4 callers (`packages/cli`, `packages/core`, `packages/adapters`) are updated in the same PR to import the concrete adapter type directly (e.g., `typeof ruleBasedCorrectionDetector` instead of `CorrectionDetector`), so the change is invisible to runtime behavior.
- **The CLAUDE.md元约束「Port 接口冻结于 M0」 still applies — but only to active ports.** Archived ports are explicitly outside the M0 freeze: they can be deleted, modified, or revived without triggering the contract-test + plan-document update protocol. This carve-out must be added to CLAUDE.md or the next CLAUDE.md regeneration cycle as a clarification.
- **Future ports must declare adapter count at introduction.** New PRs adding to `packages/ports/src/` (not `_archived/`) must demonstrate either (i) two concrete adapters merged in the same or adjacent PR, or (ii) a contract test that meaningfully exercises the interface against a non-trivial fake (in-memory adapter that is more than a typed wrapper around the prod adapter). Single-adapter ports added without one of these two justifications must go directly into `_archived/` with a TODO. This rule applies via PR review judgment; it is not currently mechanically enforced.
- **CONTEXT.md gains a new term: "Archived port"** under a new "Module structure" subsection. Domain term to disambiguate from "deprecated" (still usable) and "legacy" (still running) — see CONTEXT.md update.
- **The 4 contract test suites move into `_archived/__tests__/`** and are excluded from CI. They remain readable as a historical record of what the port-level invariants were, useful when reviving a port. Lone-adapter test cases that were valuable as unit tests must be migrated into the adapter's own `__tests__/` before the contract test is archived (commit 3/4/5 of the implementation plan handles this case-by-case).
- **Two M5 viral-sync ports archived simultaneously** carries elevated risk because M5 was merged less than a month prior to this ADR. The implementation plan (`docs/plans/2026-05-07-archive-hypothetical-ports/plan.md`) requires a successful `pnpm teamagent m5-sync --dry-run` probe before the M5 archive commit can land; if M5 grows a real second transport in a future milestone, these two ports can be moved back out of the drawer with their git history intact.
