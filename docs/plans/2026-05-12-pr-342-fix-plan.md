## Iter 1

### Task

Fix the stale `last_install_error` bug in `runUpdater`'s success path:

- **Symptom**: after the Tier-3 banner fires (Pages + npm both unreachable in one
  cycle), if Pages recovers on the next cycle but the installed version is already
  current, `runUpdater` early-returns at the "up-to-date" branch without clearing
  the stale `last_install_error` string. `maybeShowVersionCheckBanner` then keeps
  firing every SessionStart even though the underlying failure resolved.
- **Root cause**: the success-fetch `writeState` block overlays `consecutive_rate_limits`,
  `next_check_after_ts`, `last_branch_etag`, `last_branch_sha` — but **not**
  `last_install_error`. The field is reserved for install/migrate errors AND for
  the Tier-3 version-check errors; the success path only clears it in the
  npm-install-completed branch, missing the up-to-date early-return path.
- **Fix scope**: a single overlay field in `updater-logic.ts` success-fetch
  `writeState`. Selective clear: only wipe error strings that start with the
  Tier-3 prefix `"version-check failed:"`; preserve real install/migrate errors
  (different prefixes, owned by `maybeShowReinstallBanner`).

### Expected outputs

1. `packages/cli/src/updater-logic.ts` — success-fetch `writeState` adds
   `last_install_error: clearedError` field, where `clearedError = null` iff the
   stale error starts with `"version-check failed:"`, otherwise preserves.
2. Inline comment explaining why selective clear (Tier-3 owns the prefix; reinstall
   banner owns the rest).
3. Follow-up test in `updater-logic.test.ts`: stub a runUpdater cycle with
   `last_install_error = "version-check failed: ..."` pre-state, fetch returns
   success + up-to-date, assert post-state `last_install_error === null`.
   *(Deferred to iter-2 because existing `updater-logic.test.ts` uses the old
   `fetchRemoteSha` mock shape — adding a clean test requires the broader test
   migration captured in the "Known follow-up surface" of the PR body.)*

## Iter 2

### Task
CI iter-1 (Ubuntu + Windows test) failed at `pnpm typecheck` with 2 TS errors:
- `integration-issue-159.test.ts:159` — `Property 'fetchLatestVersion' is missing` (UpdaterDeps construction didn't include the new required field).
- `updater-logic.test.ts:20` — `Type 'undefined' is not assignable to type '() => Promise<FetchLatestResult>'` (factory's `Partial<UpdaterDeps>` overrides surface as optional but UpdaterDeps requires it).

### Root cause
My iter-0 design kept `fetchRemoteSha?` optional but `fetchLatestVersion` required, on UpdaterDeps. Existing test factories built UpdaterDeps without `fetchLatestVersion`. The right migration is to:
1. Provide `fetchLatestVersion` mock in all factory defaults so typecheck passes;
2. Skip the obsolete legacy tests (they test rate-limit / ETag / SHA-comparison branches that #313 deliberately removed);
3. Add fresh `#313`-aligned tests that exercise the new version-check + Tier 3 + recovery paths.

### Expected outputs
- `packages/cli/src/__tests__/updater-logic.test.ts`:
  - `makeDeps` factory adds `fetchLatestVersion: vi.fn().mockResolvedValue(okLatest("0.0.0"))`.
  - New `okLatest` / `failLatest` helpers for FetchLatestResult shapes.
  - Existing `describe("runUpdater")` wrapped in `.skip` with comment pointing here.
  - New `describe("runUpdater (#313 version-check)")` block with 6 focused tests: up-to-date, install path, Tier 3 error write, Tier 3 recovery clears stale error, non-Tier-3 errors preserved, backup uses last_installed_sha.
- `packages/cli/src/__tests__/integration-issue-159.test.ts`:
  - The runUpdater backoff lifecycle scenario (lines 130-210) wrapped in `describe.skip` + `fetchLatestVersion` mock injected to satisfy typecheck on the .skip'd body.
  - Scenarios 1-3, 5-6 (direct fetchRemoteSha unit tests) untouched — those test a function that still exists and still works.
- `packages/cli/src/__tests__/update.test.ts`:
  - Added `vi.mock("../update/fetch-latest.js", ...)` alongside the existing github-api mock.
  - Skipped two legacy describes ("per-reason error messages", "ETag and sha persistence on success" with its PR #194 backoff tests).
  - New `describe("checkCmd (#313 fetchLatestVersion)")` block with 5 tests: up-to-date version match, update available, Tier 3 message format, npm fallback source label, legacy backoff window honored.
