## Grill 问题

`SessionStart` 和 `UserPromptSubmit` 发服务器之后，到底用来干什么？

## 可选答案

A. 作为日报正文主来源
B. 作为实时 active/idle green light
C. 作为异常检测辅助信号
D. 作为 prompt 原文证据回放
E. B + C + D，不做 A

## 裁决

选 **B + C + D**。

也就是：

```txt
#308 用途：
  1. leader 首页立即显示 green light
  2. 支持异常检测：高 AI activity + 低 GitHub progress
  3. 存完整 prompt，作为 evidence / replay

#308 不做：
  不作为 #371 日报的主数据源
```

#308 的 issue body 非常短，只说“暂定 session start 和 usersubmit prompt 事件发给服务器”；这意味着它是一个事件上报底座，不应该被误解成完整日报系统。citeturn138076view4

## 设计结果

```txt
收到 SessionStart:

收到 UserPromptSubmit:
```

# 11. green light：presence state，不是完整进展判断

## Grill 问题

#308 green light 什么时候亮？

## 可选答案

A. SessionStart 后一直绿
B. UserPromptSubmit 后续绿
C. Stop 立即灰
D. active / idle / offline / error 四态
E. D + TTL 可配置

## 裁决

选 **E**。

```txt
green active:
  最近有 SessionStart / UserPromptSubmit

yellow idle:
  session 开着，但 N 分钟没有 UserPromptSubmit

gray offline:
  收到 Stop，或 TTL 过期

red error:
  hook 上报失败
  agent 掉线
  GitHub 绑定缺失
  事件解析失败
```

默认：

```txt
active_ttl = 10 分钟
idle_after = 10 分钟无 UserPromptSubmit
offline_after = 60 分钟无任何事件
Stop = 立即 offline
```

这把 #308 做成 leader 首页的即时信号，而不是误做成完整进度分析。#308 的原始需求只说发 `session start` 和 `usersubmit prompt`，所以它最适合做 presence。citeturn138076view4
