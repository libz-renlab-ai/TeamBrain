怎么验证安装

三层验证，由快到全。第二层之后的任何验证必须走第三方 judge harness（项目惯例）。

第一层 —— teamagent doctor

单一权威 CLI 检查。逐通道汇报安装状态、知识库存在性、plugin 同步、skill 传播。

$ pnpm teamagent doctor
# 期望输出：
# hook-registered ✓ (6 channels)
# plugin-sync     ✓
# skills mirror   ✓
# kb              ✓
# warmup          ✓

第二层 —— 直接看文件系统

如果 doctor 全绿，下面这些路径都必须存在并包含 TeamAgent 条目。

$ ls ~/.claude/skills/teamagent/
$ jq '.hooks | keys' ~/.claude/settings.json
$ ls ~/.claude/plugins/installed/
$ ls .teamagent/knowledge.db

第三层 —— judge harness 探针（权威）

端到端 install 回归必须走第三方 judge harness（按 docs/plans/<...>/judge.md playbook 约定）：用一次性 $HOME 跑 teamagent init，把 raw stdout/stderr/exit code 落到 .judge/<run_id>/，最后让另一只 LLM judge 只读 raw JSON 判结论 —— 永远不允许 init 给自己打分。探针最少覆盖以下场景：

  • 从干净 prefix 跑 npm install -g teamagent（PR #147 的预算 ≤3 秒）。
  • 在空仓库里跑 teamagent init（默认 --target=claude）。
  • teamagent init --target=codex —— 当前 flag 已被接受（init.ts:282 跳过 Claude hook 注册）但不安装任何 Codex 侧 hook；等 #291 把 Codex installer 分支补上。
  • teamagent doctor 退出码 = 0，所有行都绿。
  • 重复跑 init 是幂等的（hook 不重复、settings 不被改写）。
