# 6. #371 日报：GitHub-first，不是 prompt-first

## Grill 问题

日报的主数据源是什么？

## 可选答案

A. prompt 原文
B. Claude/Codex session summary
C. GitHub activity
D. audio transcript
E. GitHub-first，AI/audio 作为辅助 evidence

## 裁决

选 **E，但主源是 GitHub**。

#371 的需求是“员工每天使用完 Claude 后，统一汇总他们在多个并行项目中的操作，通过一句话总结当天工作内容，形成每日工作汇报”。它说的是“多个并行项目中的操作”和“一句话总结当天工作内容”，不是“把 prompt 摘要发给老板”。citeturn138076view9

所以日报结构应该是：

```txt
主记录：
  member × project daily summary

项目首页：
  project daily summary

成员视角：
  member daily summary，可选

明细锚点：
  Issue > PR > Branch > Commit > AI Session
```

示例：

```txt
Alice / TeamBrain:
  今天推进 Codex hook 初始化幂等与 adapter 分离，已完成配置 merge 策略讨论，尚未合并 PR。

Bob / TeamBrain:
  今天排查 Windows audio 默认设备问题，确认应默认麦克风并提供 --device 逃生口。
```

日报不是：

```txt
Alice 今天问了 Claude 38 次。
```

日报应该是：

```txt
Alice 今天在 TeamBrain 的 #291 上推进 init --target=both 的幂等 hook 安装方案。
```

# 13. #290/#291：Codex 和 Claude 接入必须 host adapter 化

## Grill 问题

Codex hook 怎么接？

## 可选答案

A. 复制 Claude hook 脚本，改到能跑
B. 完全重写 Codex 路径
C. Claude/Codex 共用能共用的 bin，shape 不同时加 adapter
D. 先只支持 Claude
E. 先只支持 Codex

## 裁决

选 **C**。

#290 明确要求 `.codex/` config 被提交和追踪，Codex adapters 要与 Claude scripts 并存，不能 mutation Claude scripts；它还特别点出 `SessionStart systemMessage envelope` shape 不同处要加 Codex-native adapter。citeturn596084view0

架构：

```txt
.claude/settings.json
  -> Claude hook
  -> claude adapter
  -> /v1/events

.codex/hooks.json
  -> Codex hook
  -> codex adapter
  -> /v1/events

server:
  raw_events
  normalized_events
```

不能这样：

```txt
Codex hook 直接改 Claude script
```

也不能这样：

```txt
每个 plugin 自己适配 Claude/Codex payload
```

# 14. `teamagent init --target=both`：默认部分成功，但必须清楚报告

## Grill 问题

Codex hook 安装失败时，Claude hook 要不要继续？

## 可选答案

A. 全部 rollback
B. Claude 成功就算成功
C. 部分成功，但 summary 明确标出失败 target
D. 交互询问
E. C + strict mode

## 裁决

选 **E**。

#291 要求 `pnpm teamagent init --target=both` 写入 Claude 和 Codex hook config；重复运行必须幂等，不能 duplicate entries，也不能 clobber 用户编辑过的 Codex config；`target=claude` 行为还必须保持不变。citeturn138076view0

默认：

```txt
teamagent init --target=both

Claude: installed
Codex: failed
Reason: existing malformed .codex/hooks.json
Next: run teamagent doctor --target=codex
Exit: warning unless --strict
```

strict：

```txt
teamagent init --target=both --strict

Any target failed:
  exit non-zero
  project not ready
```

必须支持：

```txt
--json
```

输出给 CI / doctor：

```json
{
  \"claude\": { \"status\": \"installed\" },
  \"codex\": { \"status\": \"failed\", \"reason\": \"conflict\" },
  \"ready\": false
}
```

# 15. Codex hook 幂等与不 clobber 策略

## Grill 问题

如何保证重复 init 不重复、不覆盖？

## 可选答案

A. 每次重写 `.codex/hooks.json`
B. 如果文件存在就跳过
C. 结构化 merge
D. append entry
E. 结构化 merge + idempotency tag + backup

## 裁决

选 **E**。

```txt
每条 TeamAgent hook entry:
  _teamagentTag: \"teamagent:codex-hook:v1\"
  target_event: \"SessionStart\"
  command: \"...\"

本地 state:
  .teamagent/init-state.json
  installed_targets
  hook_config_hash
  installed_at
  installer_version
```

流程：

```txt
1. 读取 .codex/hooks.json
2. 找 _teamagentTag
3. 已存在且 hash 匹配 -> noop
4. 不存在 -> merge
5. 冲突 -> 备份 + 报错，不覆盖用户配置
```

这直接响应 #291 的“idempotent、no duplicate、no clobber”。citeturn138076view0
