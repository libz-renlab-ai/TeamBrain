## Grill comments (verbatim)

### Comment 1 — @libz-renlab-ai at 2026-05-11T03:08:19Z

## 背景 / 动机

现有 digital-twin uploader 只在 Stop hook 触发时上传**当前 session**。本 issue 要求：

1. **每整点**自动上传当日**增量**日志（已传的不重传）
2. 同时上传当前 Claude Code 账号的 **Max 5h / 7d 配额百分比**
3. Dashboard 显示每个员工的两条进度条

## 设计决策（已固化）

### 1. 触发：Stop-hook-piggyback（不引入新进程）

复用现有 `packages/cli/src/bin-digital-twin-tap.ts`：

- Stop hook 入口先跑原"当前 session 上传"
- 然后判定：`now() - last_hourly_scan_at > 55min` ？
  - 是 → 跑"整点扫描"
  - 否 → 退出
- 时间戳：`~/.teamagent/digital-twin/last-hourly-scan.txt`（ISO）
- **理由**：daemon idle-self-exit、跨平台 cron 复杂；piggyback 零新进程。CEO 已表态"团队都在公司，能跑就行"。
- **trade-off**：用户 1h 内未 Stop → 错过一格；下次 Stop 时一并补发。

### 2. 增量去重：服务器是 source of truth

- 客户端整点扫描：
  1. `GET /api/sessions?user=<my>&date=<today-UTC>` → 服务器清单
  2. 扫本地 `~/.claude/projects/<sanitized-cwd>/*.jsonl`（mtime in today）
  3. **本地 ∖ 服务器** = 待上传集合
  4. 逐个 enqueue 到现有 queue/pending/
- **理由**：本地状态可能丢（重装、删 queue），服务器是 ground truth；`GET /api/sessions` endpoint 已存在，零新代码。

### 3. 配额 probe：1-token haiku 招呼

整点扫描时 POST `https://api.anthropic.com/v1/messages`：

- model `claude-haiku-4-5`, max_tokens 1, message `[{"role":"user","content":"hi"}]`
- headers: `Authorization: Bearer <accessToken from ~/.claude/.credentials.json>` + `anthropic-version: 2023-06-01` + `anthropic-beta: oauth-2025-04-20`
- 解析响应头：
  - `anthropic-ratelimit-unified-5h-utilization` (float 0-1)
  - `anthropic-ratelimit-unified-7d-utilization` (float 0-1)
  - `anthropic-ratelimit-unified-5h-reset` (unix sec)
  - `anthropic-ratelimit-unified-7d-reset` (unix sec)
- 失败 → cache 上次值，envelope 标 `quota.stale=true`
- **实测验证**：本人 OAuth token 已返回 5h=0.35 / 7d=0.42。endpoint 真实可用。
- **成本**：haiku + 1 token + 每人 24/天 ≈ 1-2 条 message 占用，Max 20x 用户无感。

### 4. Envelope 协议扩展（CcSessionEnvelope）

`packages/digital-twin/src/schemas/cc-session.ts` 增加 optional 顶级字段：

```ts
quota?: {
  subscription_tier: string;        // "max" + "default_claude_max_20x"
  five_hour_utilization: number;     // 0-1
  seven_day_utilization: number;     // 0-1
  five_hour_reset_at: number;        // unix sec
  seven_day_reset_at: number;        // unix sec
  probed_at: string;                 // ISO
  stale: boolean;                    // probe 失败用 cache 时 true
}
```

服务器 `mock-server.ts`：

- 接收 `envelope.quota` → 写覆盖式 `<outputDir>/<user>/<date>/quota.json`
- transcript 仍正常写 `<id>.jsonl`
- 新 endpoint：`GET /api/quota?user=<id>&date=<YYYY-MM-DD>` 返回最新 `quota.json`

### 5. Dashboard UI（`dashboard-html.ts`）

每个用户名旁边显示：

```
liboze2026@163.com   🔥5h ████░░ 35%   📅7d ████░░ 42%
```

- 颜色阈值：<50% 绿、50-80% 黄、>80% 红
- 数据获取：dashboard JS 加载 Users 后逐用户 `GET /api/quota?user=...&date=today`
- 缺失：显示 `—`
- `stale=true`：进度条加灰色 stale 标记

## 边界 case 处理（不开独立 issue，全在本 PR 内）

| # | case | 处理 |
|---|------|------|
| 1 | OAuth accessToken 过期（12h） | probe 收 401 → 标 `quota.stale=true` + 用 cache；不做 refresh 流程（Claude Code 自己刷） |
| 2 | 429 限流 | 同 401。响应头里仍带 utilization 时优先解析头部 |
| 3 | 多人同秒 probe 撞 IP 风控 | 引入基于 `hash(user_id) % 60` 的秒级 jitter |
| 4 | `last-hourly-scan.txt` 丢失 | 视为"从未扫描"，立即跑一次整点流程 |
| 5 | 离线 / VPN 断开 | enqueue 本地，下次有网上传；probe 失败标 stale。**不阻塞 Stop hook** |
| 6 | 时区不一致 | 一律用 UTC（现有 `dateStamp()` 已用 UTC） |
| 7 | Stop hook 期间 daemon 挂掉 | enqueue 即返回；下次任何 Stop 都会重新起 daemon（PID lock 已就位） |
| 8 | 进度条跳变（7d 窗口重置） | dashboard 不做动画，直接显示当前值 |
| 9 | 用户已 `paused`（uploader.enabled=false） | 整点扫描 skip，不 probe 配额（尊重 pause） |
| 10 | 多 Claude Code 项目并发 Stop | `last-hourly-scan.txt` 用 atomic write fence（`O_EXCL`）；抢不到的 hook 直接 skip 整点逻辑 |
